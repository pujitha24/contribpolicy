## Review notes (2026-10-12)

Each output was compared with the source documents by hand. Known gaps:

- `kubernetes-sigs/kueue`: the AI rules come from the repository's AGENTS.md and from the org registry (kubernetes.dev AI Guidance); both agree. CLA comes from CONTRIBUTING.md.
- `thanos-io/thanos`: matches CONTRIBUTING.md "AI Guidance" line by line.
- `jaegertracing/jaeger`: the AI-usage checkbox comes from the org-wide PR template in `jaegertracing/.github`. `human_only: review-replies` is **stricter than the source**: AI_POLICY.md lets AI help you word a reply you read and stand behind, and forbids letting an agent answer review feedback autonomously.
- `cortexproject/cortex` and `microsoft/agent-framework`: disclosure is conditional ("significant" / "material" AI use) and is reported as `required: true`; the condition is in the evidence quote.
- `radius-project/radius`: `restricted` with the label groups. The other conditions (issue not assigned to someone else, no open PR, re-check right before opening) are only in the evidence. No disclosure rule exists.
- `grafana/mimir`: no AI policy (`unspecified`); the signed-and-verified commit rule is detected. The doc notes that it also applies to commits authored with AI tools.
- `fluxcd/flux2`: Flux asks for disclosure in the PR description **and** an `Assisted-by` trailer; `where` lists both channels but cannot express that both are required.
- `tektoncd/pipeline`: the repository's own docs do not mention AI; every AI rule comes from the org registry entry. The trailer is "preferred" (reported `allowed`) with the PR description as the alternative.
- `tj/commander.js`: no AI policy; nothing is reported.
